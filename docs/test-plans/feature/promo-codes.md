# Test plan: feature/promo-codes

## Summary

Customers can type one promo code on the cart. `LEAFY10` takes 10% off the plant subtotal, rounded to cents, and that percentage never comes off shipping. `FREESHIP` makes shipping $0.00. Free shipping from $50.00 is still decided on the subtotal before any discount. `SPRING5` is expired and must be refused with a message that the code has expired, announced to screen-reader users as soon as it appears. A new code replaces the old one, Remove clears it, and letter case does not matter. Checkout charges that cart; the order keeps the discount and the code, and the cart forgets the code. Cart and order responses gain `discount` and `promoCode`. Expectations below are the documented ones: a failure against the app is a possible finding, not a reason to change the assertion. `web/src/types.ts`, the new CSS, and `docs/features/promo-codes.md` are covered by these rows. Nothing in `package.json` or config changed, so this plan does not schedule a full-suite run. This plan is not approved. Rows Q1–Q5 stay unresolved (`assumed — ask`) and get no test until a human resolves them.
