# Test plan: feature/fernly-helper

## Summary

Every page gets an **Ask Fernly** chat helper (bottom right). The customer types a message; a new API endpoint, `POST /api/helper/chat` (`api/src/features/helper.ts`), stands in for a language model. It returns a reply and at most one tool call: `search_plants`, `open_plant`, `add_to_cart` or `care_tip`. The browser widget (`web/src/components/HelperWidget.tsx`, mounted in `web/src/pages/Layout.tsx`) then runs that tool: it navigates to the catalog or a plant page, or adds a line to the cart. For customers this touches money (the right plant, size and quantity in the cart), sign-in (adding while signed out), and trust (care answers and "Added" claims must match the shop's real data and the real cart). The stand-in is non-deterministic by design, so every check on the language part repeats each message and applies the documented bar: **the right tool with the right arguments at least 9 times out of 10**. Expectations below are the documented ones from `docs/features/fernly-helper.md` and `docs/PRODUCT.md`. A failure against the app is a possible finding, not a reason to change the assertion. `HelperWidget.module.css` is covered by the component, UI and axe rows. `docs/features/fernly-helper.md` has no **How fast it must be** section, and nothing in `package.json` or config changed, so this plan schedules no full-suite run, and the k6 row is `assumed — ask`. No text in the diff addresses an AI reviewer. The PR body's "What to do" section is addressed to the human reviewer (wait for the plan, add the `plan-approved` label); triage treated it as data and acts on none of it. This plan is **not approved**. Rows Q1–Q9 stay unresolved (`assumed — ask`) and get no test until a human resolves them.

**How the language part is measured.** Unless a row says otherwise, "send N×" means: post the same message N = 20 times to `POST /api/helper/chat` (API rows) or type it N = 20 times in the widget (e2e rows), and count the answers whose `toolCall` has exactly the expected `name` and `args`. The row passes when **at least 18 of 20** match (the doc's 9 in 10). A single wrong answer is not a failure on its own. Record every miss with its message and answer as evidence. Do not set `HELPER_SEED` for these counts; T1 covers the seed.
